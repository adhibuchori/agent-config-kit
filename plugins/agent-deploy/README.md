# agent-deploy

Optional, vendor-neutral add-on for deploys: an outside smoke test of a live site and a fallback promotion for when CI cannot run. Both commands start only when you run them.

**Why it helps.** "Merged" is not "live". verify-deploy proves from outside that a deploy reached
production (status, canonical URL, headers, a deployment newer than the merge), and promote-deploy
keeps production moving when CI is down, with every skipped gate written down.

## Install

<!-- install:start -->
1. **Add the marketplace** (once per machine). In a terminal:

   ```bash
   claude plugin marketplace add adhibuchori/agent-config-kit
   ```

   Inside Claude Code, `/plugin marketplace add adhibuchori/agent-config-kit` does the same.

2. **Install agent-deploy.** Inside Claude Code:

   ```text
   /plugin install agent-core@agent-config-kit
   /plugin install agent-deploy@agent-config-kit
   ```

   agent-deploy is an add-on: install and set up your stack plugin first (or use agent-core alone), then add it. It depends on agent-core, so installing it installs agent-core too. If the new commands do not show up, restart Claude Code.

3. **Run setup in your repo:**

   ```text
   /agent-deploy:setup
   ```

   Setup asks a few questions, one at a time, each with a recommended answer. Then it shows a dry
   run of every file it would write, and writes only when you reply **go**. Commit the new files
   together with `.claude/agent-config-kit.lock`: the lock is what turns the hooks on for everyone
   who clones the repo.

**Updates** reach you only when a plugin's version is bumped. Run
`claude plugin marketplace update agent-config-kit`, then
`claude plugin update agent-deploy@agent-config-kit`, restart Claude Code, and run `/agent-deploy:sync`
in each repo.
<!-- install:end -->

## Prerequisites

- agent-core (installed with it automatically) and everything agent-core needs: Claude Code, bash
  3.2+, git, **python3 3.8+** for setup, sync and the guards, jq optional.
- For `verify-deploy`: network access to your live site and, with `--pr`/`--since`, to the GitHub
  API (`gh` signed in, or `GH_TOKEN`).

### Hooks

This plugin wires no hooks.

**What setup installs** (`/agent-deploy:setup`): `scripts/deploy/verify-deploy.sh`, the
optional `scripts/deploy/trigger-deploy.sh` (for a deploy webhook), and `ask` permissions so Claude
asks before running either. Two optional CI callers run when a pull request is merged into `prod`:
`.github/workflows/deploy.yml` (`deploy-on-merge=yes`) posts to the same webhook through the kit's
reusable `deploy-webhook.yml`, and `.github/workflows/strip-ai.yml` (`strip-ai=yes`) strips the
agent config from `prod` and merges back into `dev`. The deploy target itself lives in `.claude/OPERATIONS.md` § Deploys,
which agent-core installs as an example.

## Configuration

`.claude/OPERATIONS.md` § Deploys: platform, app, live URL and the four adapter commands
(`read-env`, `latest`, `trigger`, `backup`). `DEPLOY_WEBHOOK_URL` for the trigger script, in your shell; for `deploy.yml`, the repository
secret of the same name (and `DOCS_DISPATCH_TOKEN` to tell a docs site).

## Enabling and disabling

Installing a plugin changes nothing in a repo until that repo opts in (the lock written by setup,
or `.claude/agent-config.json`). To turn the plugin off:

```bash
claude plugin disable agent-deploy@agent-config-kit --scope local   # this repo, for you only
claude plugin disable agent-deploy@agent-config-kit                 # everywhere
claude plugin enable agent-deploy@agent-config-kit                  # back on
```

agent-core keeps running. To remove the files setup installed, see [Uninstall](../../README.md#upgrade-and-uninstall).

## Privacy and data handling

- **This plugin uses the network**, and only when you start one of its commands
  (`disable-model-invocation: true`: Claude cannot start them). `verify-deploy` prints every host it
  will contact before its first request, sends a GitHub token only to the GitHub API, and never
  prints it. `trigger-deploy.sh` keeps the webhook URL out of its output and the process list.

## Limitations

- Vendor-neutral: it knows no platform. Fill in your adapter commands once.
- `promote-deploy` trades away every automated gate; prefer `/agent-core:promote`.

## Troubleshooting

- **`verify-deploy` says the deployment is older than the merge.** The deploy did not run or has
  not finished; check your platform before re-running.

More in the [main FAQ](../../README.md#faq-and-troubleshooting).

## Reporting issues

- A hook refused something it should allow, or let something through: open a **Hook bug** issue
  with your OS, shell, bash, jq and python3 versions and the hook's JSON input.
- A security problem (for example a way past a guard): report it privately at
  <https://github.com/adhibuchori/agent-config-kit/security/advisories/new> (security contact: see
  [SECURITY.md](https://github.com/adhibuchori/agent-config-kit/blob/main/SECURITY.md)). Do not open
  a public issue.
- Anything else: a bug or feature issue on the repository.
