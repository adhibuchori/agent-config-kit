# Languages on a static site (next-intl)

Installed because setup was told the site ships more than one language. The usual failure is a
locale setup copied from an app: it relies on middleware to pick the language, which a static
export never runs, so every visitor lands on a 404 or on the wrong language.

## Routing

- Every page lives under `app/[locale]/`, and `generateStaticParams` in `app/[locale]/layout.tsx`
  returns every locale, so each language version is its own prerendered page (`/en/about`,
  `/id/about`).
- In export mode there is no middleware: the root path `/` is either one locale's content or a
  small static page that links to each language; it does not detect the browser's language on the
  server. A host redirect rule can send `/` to the default locale instead.
- Each page and layout calls `setRequestLocale(locale)` before any next-intl call, which keeps it
  static. Read messages with `getTranslations` in Server Components.
- Links and redirects come from the navigation helpers the next-intl routing config creates, so the
  locale prefix is never built by hand.

## Messages

- Every catalogue has the same keys. When one changes, the others change in the same commit;
  `.claude/agent-config.json` `localePairs` makes the post-edit hook remind the agent.
- No user-visible literal in JSX: text, `alt`, `aria-label`, `title`, `placeholder` and metadata all
  come from the catalogue.
- Dates and numbers go through next-intl's formatter with the page's locale, never a bare
  `toLocaleString()`, which uses the build machine's locale.

## Search engines

- `<html lang>` is the page's locale.
- Each language version lists every version plus `x-default` in `alternates.languages`, and the
  sitemap carries the same set (`seo.md`). `node scripts/check/metadata.mjs` fails a set that is
  missing `x-default`, leaves out the page itself, or is not returned by the other versions.
- A translated page is a real translation. Leave a page out of a language (and out of that
  language's sitemap entries) rather than ship it in the wrong language.

`agent-fe-nextjs-static:i18n-guard` reviews a diff against these rules.
