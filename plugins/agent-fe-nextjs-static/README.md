# agent-fe-nextjs-static

Guardrails and checks for a static Next.js site (company profile, landing page): static-export safety, SEO, accessibility, Core Web Vitals budgets and security headers, checked against the built site.

**Why it helps.** A static site fails on the host, not in `next dev`: headers that `next.config`
cannot set under export, a CSP that no longer matches the build, previews that get indexed, a slow
hero image. This plugin checks the built site itself, then reviews what scripts cannot judge.

## Install

<!-- install:start -->
1. **Add the marketplace** (once per machine). In a terminal:

   ```bash
   claude plugin marketplace add adhibuchori/agent-config-kit
   ```

   Inside Claude Code, `/plugin marketplace add adhibuchori/agent-config-kit` does the same.

2. **Install agent-fe-nextjs-static.** Inside Claude Code:

   ```text
   /plugin install agent-core@agent-config-kit
   /plugin install agent-fe-nextjs-static@agent-config-kit
   ```

   agent-fe-nextjs-static depends on agent-core, so installing it installs agent-core too. If the new commands do not show up, restart Claude Code.

3. **Run setup in your repo:**

   ```text
   /agent-fe-nextjs-static:setup
   ```

   Setup asks a few questions, one at a time, each with a recommended answer. Then it shows a dry
   run of every file it would write, and writes only when you reply **go**. Commit the new files
   together with `.claude/agent-config-kit.lock`: the lock is what turns the hooks on for everyone
   who clones the repo.

**Updates** reach you only when a plugin's version is bumped. Run
`claude plugin marketplace update agent-config-kit`, then
`claude plugin update agent-fe-nextjs-static@agent-config-kit`, restart Claude Code, and run `/agent-fe-nextjs-static:sync`
in each repo.
<!-- install:end -->

## Prerequisites

- agent-core (installed with it automatically) and everything agent-core needs: Claude Code, bash
  3.2+, git, **python3 3.8+** for setup, sync and the guards, jq optional.
- Node 20+ for the site checks (they read the build output; no dependencies of their own).
- Optional, per check: `pa11y-ci` or `@axe-core/cli` for the accessibility check, `@lhci/cli` and
  Chrome for Lighthouse budgets. A check whose tool is missing exits 2 and says what to add.

### Hooks

This plugin wires no hooks.

This plugin wires no hook of its own; agent-core's guards cover it.

**What setup installs** (`/agent-fe-nextjs-static:setup`): 12 rules (static export, SEO, security
headers, performance, responsive, forms on static hosting, analytics consent, heavy hero, and more),
11 anti-patterns, the site checks under `scripts/check/` (static export, sitemap and robots,
metadata, share images, JSON-LD, broken links, image, font and bundle budgets, security headers,
accessibility, a local static server), `scripts/check/site.config.json` (mode `auto`, `export` or
`ssg-with-endpoints`), lint and budget configs, `public/_headers` and a pull-request-only CI caller.

## Configuration

`scripts/check/site.config.json` (seeded, yours to edit): `siteUrl`, the mode, and the budgets the
checks use. With the `i18n` answer `yes`, setup seeds `.claude/agent-config.json` with
`localePairs`.

## Skills installed by reference

The plugin ships no third-party skill. For motion on a static site (a hero reveal, a menu, scroll
effects), install this one yourself, from its source; nothing of it is committed to the kit. Keep
`.claude/rules/web/performance.md` and reduced motion in mind: the skill proposes, the rules and
the budgets decide:

| Skill | What it does | Install | License and pin |
| --- | --- | --- | --- |
| [ui-animation](https://github.com/mblode/agent-skills/tree/main/skills/ui-animation) | Builds, reviews and measures UI motion: springs, gestures, scroll effects, easing fitted from a recording | `DO_NOT_TRACK=1 npx skills@1.7.0 add mblode/agent-skills --skill ui-animation --agent claude-code` | MIT, Copyright 2026 Matthew Blode (`LICENSE.md` at the repository root). No release tags, so the pin is the content hash `skills-lock.json` records |

Each installer copies the skill into `.claude/skills/<name>/` and records its source and a hash of the
tree in `skills-lock.json`; `DO_NOT_TRACK=1` stops the installer's usage reporting. Then treat it as
a dependency: read its `SKILL.md` and scripts, keep the license beside it (copy the repository's
`LICENSE.md` into `.claude/skills/ui-animation/`), commit the folder and `skills-lock.json`
together, run `bash scripts/check/skills.sh`, and accept the reviewed tree by its hash under
`vendored:` in `.skillspector-baseline.yaml`. An upgrade changes the hash and fails the scan until
someone reads it again.

## Enabling and disabling

Installing a plugin changes nothing in a repo until that repo opts in (the lock written by setup,
or `.claude/agent-config.json`). To turn the plugin off:

```bash
claude plugin disable agent-fe-nextjs-static@agent-config-kit --scope local   # this repo, for you only
claude plugin disable agent-fe-nextjs-static@agent-config-kit                 # everywhere
claude plugin enable agent-fe-nextjs-static@agent-config-kit                  # back on
```

agent-core keeps running. To remove the files setup installed, see [Uninstall](../../README.md#upgrade-and-uninstall).

## Privacy and data handling

- Its hooks (if any) run on your machine, read only their JSON input and files in your repo, and open
  no network connection. No telemetry, nothing downloaded at run time.
- Commands and agents read your repo; agents report and never edit.
- The checks serve the build on 127.0.0.1 only. `/agent-fe-nextjs-static:launch-checklist` contacts
  the live origin only when you pass it.

## Limitations

- Conflicts with agent-fe-nextjs (one frontend stack per repo) and the other primary stacks.
- A hash-based CSP must be refreshed on every build (`security-headers.mjs --print-hashes`).
- Lighthouse numbers depend on the machine; budgets are a floor, not a lab measurement.

## Troubleshooting

- **`a11y.mjs` or `check:lighthouse` exits 2.** The tool is not a dev dependency, or no build
  exists. Build first, then add `pa11y-ci` or `@lhci/cli`.
- **`security-headers.mjs` fails right after a rebuild.** Next.js changed its inline script hashes;
  update `public/_headers` from `--print-hashes`.

More in the [main FAQ](../../README.md#faq-and-troubleshooting).

## Reporting issues

- A hook refused something it should allow, or let something through: open a **Hook bug** issue
  with your OS, shell, bash, jq and python3 versions and the hook's JSON input.
- A security problem (for example a way past a guard): report it privately at
  <https://github.com/adhibuchori/agent-config-kit/security/advisories/new> (security contact: see
  [SECURITY.md](https://github.com/adhibuchori/agent-config-kit/blob/main/SECURITY.md)). Do not open
  a public issue.
- Anything else: a bug or feature issue on the repository.
