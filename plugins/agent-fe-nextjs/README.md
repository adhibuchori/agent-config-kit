# agent-fe-nextjs

Guardrails and gates for a Next.js web app with a generated API client: the generated-guard hook, a Next.js reviewer and i18n and SEO validators, accessibility and separation-of-concerns audits, and the gate scripts setup installs.

**Why it helps.** In a Next.js app the costly mistakes are hand edits to a generated API client,
logic creeping into components, and layers importing the wrong way. This plugin refuses the first,
gates the other two, and adds reviewers for accessibility, i18n and SEO.

## Install

<!-- install:start -->
1. **Add the marketplace** (once per machine). In a terminal:

   ```bash
   claude plugin marketplace add adhibuchori/agent-config-kit
   ```

   Inside Claude Code, `/plugin marketplace add adhibuchori/agent-config-kit` does the same.

2. **Install agent-fe-nextjs.** Inside Claude Code:

   ```text
   /plugin install agent-core@agent-config-kit
   /plugin install agent-fe-nextjs@agent-config-kit
   ```

   agent-fe-nextjs depends on agent-core, so installing it installs agent-core too. If the new commands do not show up, restart Claude Code.

3. **Run setup in your repo:**

   ```text
   /agent-fe-nextjs:setup
   ```

   Setup asks a few questions, one at a time, each with a recommended answer. Then it shows a dry
   run of every file it would write, and writes only when you reply **go**. Commit the new files
   together with `.claude/agent-config-kit.lock`: the lock is what turns the hooks on for everyone
   who clones the repo.

**Updates** reach you only when a plugin's version is bumped. Run
`claude plugin marketplace update agent-config-kit`, then
`claude plugin update agent-fe-nextjs@agent-config-kit`, restart Claude Code, and run `/agent-fe-nextjs:sync`
in each repo.
<!-- install:end -->

## Prerequisites

- agent-core (installed with it automatically) and everything agent-core needs: Claude Code, bash
  3.2+, git, **python3 3.8+** for setup, sync and the guards, jq optional.
- For the installed gates: bun, TypeScript, oxlint, oxfmt, knip, vitest and husky as dev
  dependencies. A gate whose tool is missing fails, so add them before relying on `gates.sh`.

**What setup installs** (`/agent-fe-nextjs:setup`): TypeScript and web rules that load per file type,

`.oxfmtrc.json`, `knip.ts`, `.husky/pre-commit`, a pull-request-only CI caller of the kit's
`fe-nextjs-quality-gate`, PR templates, CODEOWNERS, `.gitleaks.toml` and env examples. Optional
modules, one question each: i18n, dialogs, responsive, skeletons, React Doctor in CI, design docs.

## Configuration

`generatedPaths` in `.claude/agent-config.json` (see [agent-core's table](../agent-core/README.md#configuration)).
With the `i18n` answer `yes`, setup seeds `.claude/agent-config.json` with `localePairs` for your
catalogues.

## Enabling and disabling

Installing a plugin changes nothing in a repo until that repo opts in (the lock written by setup,
or `.claude/agent-config.json`). To turn the plugin off:

```bash
claude plugin disable agent-fe-nextjs@agent-config-kit --scope local   # this repo, for you only
claude plugin disable agent-fe-nextjs@agent-config-kit                 # everywhere
claude plugin enable agent-fe-nextjs@agent-config-kit                  # back on
```

agent-core keeps running. To remove the files setup installed, see [Uninstall](../../README.md#upgrade-and-uninstall).

## Privacy and data handling

- Its hooks (if any) run on your machine, read only their JSON input and files in your repo, and open
  no network connection. No telemetry, nothing downloaded at run time.
- Commands and agents read your repo; agents report and never edit.
- The `react-doctor` skill runs only when you type `/agent-fe-nextjs:react-doctor`. It uses your
  project's React Doctor CLI; without one it asks before it downloads `react-doctor@0.9.14` from
  npm once. Every scan passes `--no-score --no-supply-chain`, so results stay local unless you
  agree otherwise.
- The optional React Doctor CI workflow (setup's `react-doctor-ci`, recommended **no**) runs the
  vendor's action, which reports to the vendor's score service.

## Limitations

- One primary stack per repo: setup refuses a repo already set up with another stack plugin
  (agent-fe-nextjs-static, agent-be-hono, agent-ai-fastapi, agent-docs-nextra).
- A shell command that writes a generated file (a redirect, `sed -i`) is not refused: the generator
  itself writes through the shell.
- `tsconfig.json` and `vitest.config.ts` are not merged; the draft prints the lines to add by hand.

## Troubleshooting

- **A gate fails with "script not found".** The gate names a package script setup adds only when
  `package.json` exists; add the script or remove the line from `scripts/check/gates.list`.
- **Edits to your own generated folder are allowed.** Add it to `generatedPaths`.

More in the [main FAQ](../../README.md#faq-and-troubleshooting).

## Reporting issues

- A hook refused something it should allow, or let something through: open a **Hook bug** issue
  with your OS, shell, bash, jq and python3 versions and the hook's JSON input.
- A security problem (for example a way past a guard): report it privately at
  <https://github.com/adhibuchori/agent-config-kit/security/advisories/new> (security contact: see
  [SECURITY.md](https://github.com/adhibuchori/agent-config-kit/blob/main/SECURITY.md)). Do not open
  a public issue.
- Anything else: a bug or feature issue on the repository.
