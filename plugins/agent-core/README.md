# agent-core

The base every kit plugin depends on: the guards that refuse destructive commands, the unlock for `.env` files and production writes, the everyday workflow commands, and the setup engine.

**Why it helps.** A rule in `CLAUDE.md` is a request; a hook that exits 2 is a wall. agent-core
refuses the handful of commands you would regret (a force-push to `main`, `rm -rf src`, `cat .env`,
a production `DELETE`), keeps `.env` files and production writes locked until you open them, and
gives every repo the same plan, review, commit, pull request and merge flow.

## Install

<!-- install:start -->
1. **Add the marketplace** (once per machine). In a terminal:

   ```bash
   claude plugin marketplace add adhibuchori/agent-config-kit
   ```

   Inside Claude Code, `/plugin marketplace add adhibuchori/agent-config-kit` does the same.

2. **Install agent-core.** Inside Claude Code:

   ```text
   /plugin install agent-core@agent-config-kit
   ```

   Most repos add one stack plugin as well; each one installs agent-core as its dependency, and its own setup plans agent-core's files in the same draft. If the new commands do not show up, restart Claude Code.

3. **Run setup in your repo:**

   ```text
   /agent-core:setup
   ```

   Setup asks a few questions, one at a time, each with a recommended answer. Then it shows a dry
   run of every file it would write, and writes only when you reply **go**. Commit the new files
   together with `.claude/agent-config-kit.lock`: the lock is what turns the hooks on for everyone
   who clones the repo.

**Updates** reach you only when a plugin's version is bumped. Run
`claude plugin marketplace update agent-config-kit`, then
`claude plugin update agent-core@agent-config-kit`, restart Claude Code, and run `/agent-core:sync`
in each repo.
<!-- install:end -->

Every stack plugin installs agent-core as its dependency, so you rarely install it alone. Alone, it suits any repo: run `/agent-core:setup`.

## Prerequisites

- Claude Code 2.1 or newer, run as the CLI or IDE extension. **claude.ai and Cowork do not install
  plugins that have a `bin/` folder**, and agent-core ships its setup engine in `bin/`
  (`agent-setup`, `agent-sync`). Its hooks and commands therefore need Claude Code itself.
- bash 3.2 or newer (macOS `/bin/bash` works) and git.
- **python3 3.8 or newer.** The command analyzer, db-guard, the config loader and the setup engine
  need it. Without python3, safety-check falls back to a few plain-text rules, and db-guard refuses
  every call to the production SQL tool in an opted-in repo (it fails closed); other MCP tools pass.
- jq is optional: faster payload reads, and the reader of last resort when python3 is missing.
- Linux and WSL2 need `bubblewrap` and `socat` for the optional Bash sandbox; macOS needs nothing.
- For the GitHub commands (`create-pr`, `merge-pr`, `promote`, ...): the GitHub CLI `gh`, signed in.

agent-core also ships `lib.sh` (shared by every hook, an exact copy in each plugin with a hook) and
`setup-check.sh`, which says at session start when a repo opted in but has no lock, or when the lock
is older than the installed plugin. Neither is a component, so neither has a docs page.

**What setup installs** (`/agent-core:setup`): permissions and the Bash sandbox in
`.claude/settings.json`; type and dead-code rules for TypeScript and/or Python; the working
agreements; `scripts/check/gates.sh`, `ai-config.sh`, `skills.sh`, `double-assertion.sh`,
`folder-shape.mjs`; `scripts/ops/pr-ready.sh` and `unlock.sh`; `scripts/env/show.sh` and `set.sh`;
`docs/unlock.md`; example ops docs under `.claude/`; and, if you want it, the kit's `.mcp.json`.

## Configuration

All keys are optional; a key you set replaces its default whole (list the defaults you still
want). A malformed key falls back to its default and Claude is warned. The template
`.claude/agent-config.example.json` (installed by setup) documents each key with its default.

| Key | Used by | Default | What it changes |
| --- | --- | --- | --- |
| `protectedBranches` | safety-check, mcp-guard | `["dev", "prod", "main", "master"]` | Branches Claude never pushes to, deletes or writes to through GitHub MCP |
| `protectedPaths` | safety-check | `src`, `app`, `components`, `content`, `tests`, `scripts`, `.claude`, `.github`, `.git`, `CLAUDE.md`, `AGENTS.md`, … | What `rm -r` and `git clean -f -- <path>` may never take |
| `commandWrappers` | safety-check | `[]` (plus built-in `sudo`, `env`, `timeout`, `npx`, `rtk`, …) | Extra wrappers to peel before judging, e.g. `"dotenvx run -f= --env-file="` |
| `dbWriteGuard.toolPattern` | db-guard | `"mcp__db-prod__execute_sql"` | Regex naming your production SQL tool |
| `localePairs` | post-edit | `[]` (off) | Files that change together, e.g. `[["messages/en.json", "messages/id.json"]]` |
| `generatedPaths` | generated-guard (stack plugins) | `src/lib/api/generated`, `src/generated`, `openapi.json`, `openapi.yaml`, `openapi.yml` | Generated output Claude may not hand-edit |
| `migrationsDirs` | migration-guard (stack plugins) | `src/db/migrations`, `drizzle`, `src/app/db/migrations/versions`, `alembic/versions`, `migrations/versions` | Generated migrations Claude may not hand-edit |

Environment variables, all optional: `AGENT_WORKSPACE_ROOT` (a folder that holds several repos, for
multi-repo sessions) and `AGENT_HOOK_STATE_DIR` (where per-session hook state lives; default
`$CLAUDE_PLUGIN_DATA/hook-state`).

## Enabling and disabling

Installing a plugin changes nothing in a repo until that repo opts in (the lock written by setup,
or `.claude/agent-config.json`). To turn the plugin off:

```bash
claude plugin disable agent-core@agent-config-kit --scope local   # this repo, for you only
claude plugin disable agent-core@agent-config-kit                 # everywhere
claude plugin enable agent-core@agent-config-kit                  # back on
```

agent-core cannot be disabled while a stack plugin that depends on it is enabled: disable the stack plugin first. Deleting `.claude/agent-config-kit.lock` and `.claude/agent-config.json` is not an off switch:
the hooks stay quiet only on machines that never saw this repo opted in. A machine that did keeps
guarding the repo with the defaults and says so. To stop them there, disable the plugin for this
project (`--scope local` above) or remove the repo's line from `opted-in-projects` in the plugin's
data folder.

## Privacy and data handling

- Every hook runs on your machine, reads only its JSON input and files in your repo, and opens no
  network connection. No telemetry. Nothing is downloaded at run time.
- The commands that push or call GitHub (`create-pr`, `merge-pr`, `resolve-pr-review`, `ship`,
  `promote`, `branch-cleanup`) use the network, and only when you type them: Claude cannot start
  them on its own.
- Hook state (the HEAD a commit started from) lives in `$CLAUDE_PLUGIN_DATA/hook-state`, per
  session, pruned after two idle days. Nothing is written under the plugin folder.
- `.env*` values never pass through a hook's output. `scripts/env/show.sh` masks secrets;
  `scripts/env/set.sh` logs key names only and keeps backups in `.claude/state/env-backups/`
  (mode 0600, gitignored by setup).

## Limitations

- Plugins cannot ship permissions, the sandbox setting or `.claude/rules/`, so `/agent-core:setup`
  writes them into your repo (after a dry run you approve).
- The hooks read command text. A script Claude writes and then runs is executed, not read; programs
  that run their own commands (`watch`, `parallel`, an editor) are judged by name only. The shell
  may not change the hooks themselves, the probes, the unlock script, the `.env` helpers or the files
  that turn the guards on; a change goes through the Edit tool or your own `!`. The Bash sandbox is
  the layer the operating system enforces. [docs/unlock.md](../../docs/unlock.md) lists the honest
  limits.
- No per-hook switch: Claude Code enables or disables a plugin as a whole. The settings above narrow
  single rules.
- Not for claude.ai or Cowork (the `bin/` rule above).

## Troubleshooting

- **"db-guard reads SQL with python3, which is not installed" on the SQL tool.** Install python3
  3.8 or newer; db-guard fails closed on its own tool, and on every MCP call when `toolPattern`
  uses more than plain names, `|` and `( )`.
- **A hook blocked something legitimate.** Read the `BLOCKED:` reason Claude quotes; it says why and
  what to do instead. If the command is right, run it yourself with `!`. If a rule is too broad for
  your repo, narrow it in `.claude/agent-config.json`, or open a hook bug with the exact command.
- **`/agent-core:setup` says `agent-setup` is not found.** agent-core is not enabled in this session
  (or you are on claude.ai or Cowork). Enable it with `/plugin` and restart Claude Code.
- **Hooks do nothing.** The repo has not opted in: run setup, or check that
  `.claude/agent-config-kit.lock` exists at the repo root.
- **Each hook seems to run twice.** Double wiring: `/agent-core:sync --check` exits 4 and names the
  entry in `.claude/settings.json` to delete.

More in the [main FAQ](../../README.md#faq-and-troubleshooting).

## Reporting issues

- A hook refused something it should allow, or let something through: open a **Hook bug** issue
  with your OS, shell, bash, jq and python3 versions and the hook's JSON input.
- A security problem (for example a way past a guard): report it privately at
  <https://github.com/adhibuchori/agent-config-kit/security/advisories/new> (security contact: see
  [SECURITY.md](https://github.com/adhibuchori/agent-config-kit/blob/main/SECURITY.md)). Do not open
  a public issue.
- Anything else: a bug or feature issue on the repository.
