# /agent-core:commit — Quality Gate & Commit Message

1. **Quality gate.** Run `bash scripts/check/gates.sh` when the repo has `scripts/check/gates.list`;
   otherwise the gates CLAUDE.md § Quality Gates lists. Fix what fails at its cause, then re-run. Do
   not proceed from a broken state. A repo with neither has no gate: say so with the draft.

2. **Inspect**: `git diff --staged` and `git status`, read whole. With RTK installed, run them as
   `rtk proxy git diff --staged` and `rtk proxy git status`: its rewrite condenses both and can drop
   lines without saying so.
   - **Never commit**: `.env*` (except the `.example` templates), or generated output that was not
     regenerated by its own generator (`generatedPaths` and `migrationsDirs` in
     `.claude/agent-config.json` name them).
   - `.claude/settings.json` goes in a commit of its own, never swept into another change.

3. **Stage explicitly** by name, and commit by pathspec (`git commit -- <paths>`). Never
   `git add -A` or `git add .`: staging everything is `/agent-core:ship`'s alone, because only
   `/agent-core:ship` runs the guards that make it safe.

4. **Draft the message** in CLAUDE.md § Commit Format; where the repo has none:

   ```text
   type: subject — max 50 characters

   [Optional body explaining the why, wrapped at 72 characters]
   ```

   - **Types**: `feat` · `fix` · `refactor` · `chore` · `docs` · `test` · `perf` · `ci`
   - **Subject**: imperative, lowercase, no trailing period, no scope prefix
   - Add whatever attribution trailer your harness or team requires; never hard-code a model name.

Output the drafted message. Do not run the commit itself.
