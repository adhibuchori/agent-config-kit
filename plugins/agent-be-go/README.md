# agent-be-go

Guardrails and gates for a Go HTTP service on PostgreSQL (net/http, oapi-codegen, pgx, sqlc, goose):
two guard hooks, a reviewer, two procedure skills, and the rules, seeded skeleton, checks and
pull-request CI setup installs.

> **Experimental (0.x).** The rule numbers, file layout and setup questions may still change
> before 1.0.0; the CHANGELOG says what to do when they do.

**Why it helps.** The regressions that cost most in a Go service are structural: a handler that
queries the database, an error code nobody registered, a route the spec does not know, a migration
edited after it ran, a foreign key without an index, a pool sized by the CPU count. This plugin
turns each into a compile error, a lint error, a test or a gate, and its reviewer cites the rule
number for the rest.

## Install

<!-- install:start -->
1. **Add the marketplace** (once per machine). In a terminal:

   ```bash
   claude plugin marketplace add adhibuchori/agent-config-kit
   ```

   Inside Claude Code, `/plugin marketplace add adhibuchori/agent-config-kit` does the same.

2. **Install agent-be-go.** Inside Claude Code:

   ```text
   /plugin install agent-core@agent-config-kit
   /plugin install agent-be-go@agent-config-kit
   ```

   agent-be-go depends on agent-core, so installing it installs agent-core too. If the new commands do not show up, restart Claude Code.

3. **Run setup in your repo:**

   ```text
   /agent-be-go:setup
   ```

   Setup asks a few questions, one at a time, each with a recommended answer. Then it shows a dry
   run of every file it would write, and writes only when you reply **go**. Commit the new files
   together with `.claude/agent-config-kit.lock`: the lock is what turns the hooks on for everyone
   who clones the repo.

**Updates** reach you only when a plugin's version is bumped. Run
`claude plugin marketplace update agent-config-kit`, then
`claude plugin update agent-be-go@agent-config-kit`, restart Claude Code, and run `/agent-be-go:sync`
in each repo.
<!-- install:end -->

## Prerequisites

- agent-core (installed with it automatically) and everything agent-core needs: Claude Code, bash
  3.2+, git, **python3 3.8+** for setup, sync and the guards, jq optional.
- For the installed gates: Go 1.27, golangci-lint v2.14.0, gitleaks, Node 20 or newer, and a
  PostgreSQL 18 the tests can reach (a throwaway container is enough). The other Go tools
  (oapi-codegen, sqlc, goose, govulncheck) are pinned in `go.mod` and run with `go tool`.
- Recommended: the official `gopls-lsp` plugin, for gopls diagnostics after each edit.

**What setup installs** (`/agent-be-go:setup`): a 27-rule `AGENTS.md` index and a short `CLAUDE.md`
starter; rules for the Go service, PostgreSQL (shared with agent-be-axum), testing, error codes and
coverage, each loaded only for the files it covers; 17 anti-patterns; a service skeleton with its
tests at 100% (`cmd/api`, `internal/apperr` with the closed error-code registry and the RFC 9457
writer, `internal/httpapi` with the generated server, validation, the 404/405 fallback and the
handler-size test, `internal/config`, `internal/logging`, `internal/postgres` with the pool and the
pooler test), `api/openapi.yaml` and its export, `db/roles.sql`, `.golangci.yml`, `sqlc.yaml`,
`.squawk.toml`, the gate scripts with `gates.list`, `.githooks/pre-commit`, a pull-request-only CI
caller of `be-go-quality-gate`, PR templates and a CODEOWNERS starter. Optional: a DeepSeek review of
each pull request (`deepseek-review`, needs the `DEEPSEEK_API_KEY` secret).

## Configuration

In `.claude/agent-config.json` (setup seeds it): `appendOnlyMigrationsDirs` (`db/migrations`) and
`generatedPaths` (`api/openapi.json`, `internal/httpapi/api.gen.go`, `internal/postgres/db`); see
[agent-core's table](../agent-core/README.md#configuration).

## Enabling and disabling

Installing a plugin changes nothing in a repo until that repo opts in (the lock written by setup,
or `.claude/agent-config.json`). To turn the plugin off:

```bash
claude plugin disable agent-be-go@agent-config-kit --scope local   # this repo, for you only
claude plugin disable agent-be-go@agent-config-kit                 # everywhere
claude plugin enable agent-be-go@agent-config-kit                  # back on
```

agent-core keeps running. To remove the files setup installed, see [Uninstall](../../README.md#upgrade-and-uninstall).

## Privacy and data handling

- Its hooks run on your machine, read only their JSON input and files in your repo, and open no
  network connection. No telemetry, nothing downloaded at run time.
- Commands and agents read your repo; agents report and never edit.

## Limitations

- One primary stack per repo.
- The seeded files import `example.com/service`: replace it with your module path once.
- The guards protect files from Claude's file tools; review migrations and generated code in the
  pull request like any other change.

## Troubleshooting

- **The migration guard never fires.** The repo has no `db/migrations` yet, or
  `.claude/agent-config.json` does not list it.
- **The coverage gate says `TEST_DATABASE_URL is not set`.** Run it through
  `scripts/check/ci-env.sh` (as `gates.list` does), with the test database from
  `.claude/rules/backend/testing.md` running.

More in the [main FAQ](../../README.md#faq-and-troubleshooting).

## Reporting issues

- A hook refused something it should allow, or let something through: open a **Hook bug** issue
  with your OS, shell, bash, jq and python3 versions and the hook's JSON input.
- A security problem (for example a way past a guard): report it privately at
  <https://github.com/adhibuchori/agent-config-kit/security/advisories/new> (security contact: see
  [SECURITY.md](https://github.com/adhibuchori/agent-config-kit/blob/main/SECURITY.md)). Do not open
  a public issue.
- Anything else: a bug or feature issue on the repository.
