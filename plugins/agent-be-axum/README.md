# agent-be-axum

Guardrails and gates for a Rust + Axum service on PostgreSQL (sqlx, utoipa): two guards, a backend reviewer, two skills, and the rules, checks, service skeleton and pull-request CI setup installs. **Experimental (0.x):** names and rules may still change before 1.0.0.

**Why it helps.** Most API regressions are structural: a handler that queries the database, a
query in a loop, an error that leaves without a code, a route the spec never lists, a migration
edited after it ran. In Rust the compiler can hold most of these: module privacy keeps the layers
apart, a closed `ErrorCode` enum fails the build when a code is unregistered or unused, and clippy
runs with every warning as an error. What the compiler cannot see, a check script or the reviewer
does, and each one cites a rule number.

## Install

<!-- install:start -->
1. **Add the marketplace** (once per machine). In a terminal:

   ```bash
   claude plugin marketplace add adhibuchori/agent-config-kit
   ```

   Inside Claude Code, `/plugin marketplace add adhibuchori/agent-config-kit` does the same.

2. **Install agent-be-axum.** Inside Claude Code:

   ```text
   /plugin install agent-core@agent-config-kit
   /plugin install agent-be-axum@agent-config-kit
   ```

   agent-be-axum depends on agent-core, so installing it installs agent-core too. If the new commands do not show up, restart Claude Code.

3. **Run setup in your repo:**

   ```text
   /agent-be-axum:setup
   ```

   Setup asks a few questions, one at a time, each with a recommended answer. Then it shows a dry
   run of every file it would write, and writes only when you reply **go**. Commit the new files
   together with `.claude/agent-config-kit.lock`: the lock is what turns the hooks on for everyone
   who clones the repo.

**Updates** reach you only when a plugin's version is bumped. Run
`claude plugin marketplace update agent-config-kit`, then
`claude plugin update agent-be-axum@agent-config-kit`, restart Claude Code, and run `/agent-be-axum:sync`
in each repo.
<!-- install:end -->

## Prerequisites

- agent-core (installed with it automatically) and everything agent-core needs: Claude Code, bash
  3.2+, git, **python3 3.8+** for setup, sync and the guards, jq optional.
- For the installed gates: the toolchain `rust-toolchain.toml` pins (Rust 1.99.0 with clippy,
  rustfmt and llvm-tools), cargo-llvm-cov 0.9.1, cargo-nextest 0.9.148, Node 20+, gitleaks, and
  PostgreSQL 18 for the database tier. The CI gate adds cargo-deny 0.20.2 and sqlx-cli 0.9.0.

**What setup installs** (`/agent-be-axum:setup`): backend rules (the service layout, PostgreSQL,
testing, error codes, coverage), anti-patterns, a service skeleton (`src/platform/` with the error
contract, the `ValidJson` extractor, the layers, the pool and the configuration; a health and a
readiness route; the handler, database and pooler test tiers; `openapi.json`; `build.rs`), the
database roles (`db/roles.sql`, shared with agent-be-go), clippy, rustfmt,
cargo-deny, nextest and toolchain config, the check scripts with `gates.list`, `.githooks/pre-commit`,
a pull-request-only CI caller of `be-axum-quality-gate`, PR templates and a CODEOWNERS starter.
`Cargo.toml` comes from a starter in a new repo; an existing one takes a by-hand snippet. Optional:
a DeepSeek review of each pull request (`deepseek-review`, needs the `DEEPSEEK_API_KEY` secret),
and the payload contract (`payload-encryption`, recommended no): sealed request and response
bodies, ECDH P-256 key agreement for public clients such as an iOS app, key rings for server
callers and a generated endpoint registry, in `src/payload/` and `src/routes/payload*.rs`. It is
installed unwired; `src/payload/mod.rs` lists the by-hand steps, and the registry gate stays red
until the spec lists the `ENVELOPE_*` codes.

## Configuration

`.claude/agent-config.json`, written by setup when the service owns its schema: `generatedPaths`
(`.sqlx`, `openapi.json`) and `appendOnlyMigrationsDirs` (`migrations`); see
[agent-core's table](../agent-core/README.md#configuration).

`payload.config.json`, written by setup when you answer `payload-encryption=yes`: the committed
switch (`strict`), the route exemptions with their reasons, the handshake operation, and the
peers to compare with.

## Enabling and disabling

Installing a plugin changes nothing in a repo until that repo opts in (the lock written by setup,
or `.claude/agent-config.json`). To turn the plugin off:

```bash
claude plugin disable agent-be-axum@agent-config-kit --scope local   # this repo, for you only
claude plugin disable agent-be-axum@agent-config-kit                 # everywhere
claude plugin enable agent-be-axum@agent-config-kit                  # back on
```

agent-core keeps running. To remove the files setup installed, see [Uninstall](../../README.md#upgrade-and-uninstall).

## Privacy and data handling

- Its hooks run on your machine, read only their JSON input and files in your repo, and open no
  network connection. No telemetry, nothing downloaded at run time.
- Commands, skills and agents read your repo; agents report and never edit.

## Limitations

- One primary stack per repo.
- The guards protect files from Claude's file tools; a shell redirect still writes. Review
  migrations and generated files in the pull request like any other code.
- The seeded skeleton names its library `service`; an existing crate wires the seeded files itself.

## Troubleshooting

- **A build fails with "this lint expectation is unfulfilled" on `mod extract;`.** Your first route
  now reads a JSON body: delete that `expect(dead_code)` attribute.
- **The coverage gate fails to connect.** The database tier needs PostgreSQL at the `DATABASE_URL`
  in `.env.ci.example`.

More in the [main FAQ](../../README.md#faq-and-troubleshooting).

## Reporting issues

- A hook refused something it should allow, or let something through: open a **Hook bug** issue
  with your OS, shell, bash, jq and python3 versions and the hook's JSON input.
- A security problem (for example a way past a guard): report it privately at
  <https://github.com/adhibuchori/agent-config-kit/security/advisories/new> (security contact: see
  [SECURITY.md](https://github.com/adhibuchori/agent-config-kit/blob/main/SECURITY.md)). Do not open
  a public issue.
- Anything else: a bug or feature issue on the repository.
