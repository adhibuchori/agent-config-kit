# agent-docs-nextra

Guardrails and gates for a Nextra documentation site: the generated-guard hook, security and SEO reviewers for docs, and the rules, gate scripts and pull-request CI setup installs.

**Why it helps.** A docs site breaks quietly: a generated page edited by hand is overwritten on the
next run, a secret read at build time ends up in the public export, a missing canonical or sitemap
hides pages from search. This plugin guards the generated pages and reviews headers, CSP and
metadata.

## Install

<!-- install:start -->
1. **Add the marketplace** (once per machine). In a terminal:

   ```bash
   claude plugin marketplace add adhibuchori/agent-config-kit
   ```

   Inside Claude Code, `/plugin marketplace add adhibuchori/agent-config-kit` does the same.

2. **Install agent-docs-nextra.** Inside Claude Code:

   ```text
   /plugin install agent-core@agent-config-kit
   /plugin install agent-docs-nextra@agent-config-kit
   ```

   agent-docs-nextra depends on agent-core, so installing it installs agent-core too. If the new commands do not show up, restart Claude Code.

3. **Run setup in your repo:**

   ```text
   /agent-docs-nextra:setup
   ```

   Setup asks a few questions, one at a time, each with a recommended answer. Then it shows a dry
   run of every file it would write, and writes only when you reply **go**. Commit the new files
   together with `.claude/agent-config-kit.lock`: the lock is what turns the hooks on for everyone
   who clones the repo.

**Updates** reach you only when a plugin's version is bumped. Run
`claude plugin marketplace update agent-config-kit`, then
`claude plugin update agent-docs-nextra@agent-config-kit`, restart Claude Code, and run `/agent-docs-nextra:sync`
in each repo.
<!-- install:end -->

## Prerequisites

- agent-core (installed with it automatically) and everything agent-core needs: Claude Code, bash
  3.2+, git, **python3 3.8+** for setup, sync and the guards, jq optional.
- For the installed gates: bun, husky, knip, oxfmt, oxlint, TypeScript and `@types/bun`. The build
  needs pagefind. The optional deploy workflow needs wrangler 3.114.17 and three repository
  secrets.

### Hooks

| Hook | Event | Matcher | Data it reads | Block or warn | Timeout | Network |
| --- | --- | --- | --- | --- | --- | --- |
| [generated-guard](../../docs/agent-docs-nextra/generated-guard.md) | PreToolUse | `Write`, `Edit`, `MultiEdit` and Serena's write tools | the target path; `generatedPaths` | **blocks** (exit 2) | 10 s | no |

**What setup installs** (`/agent-docs-nextra:setup`): the docs-content rule, anti-patterns, gate
scripts and comment checks, oxlint, oxfmt and knip config, the env helper
(`bun run env:init`), a pull-request-only CI caller, a CODEOWNERS starter and, if you want them, the
changelog and deploy workflows, React Doctor and a DeepSeek review of each pull request.

## Configuration

`generatedPaths` in `.claude/agent-config.json`. The `generated-pages` answer `yes` seeds it with
`content/technical` and `content/changelog.mdx`. `"generatedPaths": []` turns the guard off.

## Enabling and disabling

Installing a plugin changes nothing in a repo until that repo opts in (the lock written by setup,
or `.claude/agent-config.json`). To turn the plugin off:

```bash
claude plugin disable agent-docs-nextra@agent-config-kit --scope local   # this repo, for you only
claude plugin disable agent-docs-nextra@agent-config-kit                 # everywhere
claude plugin enable agent-docs-nextra@agent-config-kit                  # back on
```

agent-core keeps running. To remove the files setup installed, see [Uninstall](../../README.md#upgrade-and-uninstall).

## Privacy and data handling

- Its hooks (if any) run on your machine, read only their JSON input and files in your repo, and open
  no network connection. No telemetry, nothing downloaded at run time.
- Commands and agents read your repo; agents report and never edit.
- The optional CI workflows run on GitHub, not on your machine: the changelog job reads the GitHub
  API, and the React Doctor job (setup's `react-doctor`, recommended **no**) runs the vendor's
  action, which reports to the vendor's score service. The DeepSeek review (`deepseek-review`,
  recommended **no**) sends the pull request's diff to DeepSeek's API.

## Limitations

- A shell command that writes a generated page is not refused (the generators write through
  the shell).
- One primary stack per repo.

## Troubleshooting

- **The guard blocks a page you write by hand.** Remove it from `generatedPaths`.

More in the [main FAQ](../../README.md#faq-and-troubleshooting).

## Reporting issues

- A hook refused something it should allow, or let something through: open a **Hook bug** issue
  with your OS, shell, bash, jq and python3 versions and the hook's JSON input.
- A security problem (for example a way past a guard): report it privately at
  <https://github.com/adhibuchori/agent-config-kit/security/advisories/new> (security contact: see
  [SECURITY.md](https://github.com/adhibuchori/agent-config-kit/blob/main/SECURITY.md)). Do not open
  a public issue.
- Anything else: a bug or feature issue on the repository.
